# Gameplay QoL：目标信息、疾跑与拾取优先级

本增量集中处理三个高频操作体验问题，并保持现有单机/多人输入 contract 不分叉。

## Jade 风格目标信息 HUD

当 HUD 正常显示且没有打开暂停/背包/工作台/聊天界面时，客户端每 50 ms 最多刷新一次准星目标信息。

方块信息来自现有 `BLOCKS` / `ITEMS` 规则，而不是 UI 自己维护副本：

- 方块名称；
- 要求工具（例如石头要求镐）；
- 当前快捷栏选中物是否满足工具要求；
- 当前条件下是否会产生挖掘掉落以及掉落物名称；
- 硬度；
- 方块图标。

生物信息直接从现有被动/敌对生物定义和运行时实体状态读取：

- 名称；
- 当前生命 / 最大生命；
- 生命条；
- 被动或敌对分类。

方块与生物同时位于准星方向时，显示距离更近的目标。HUD 只读运行时状态，不参与方块破坏、战斗判定或 multiplayer authority。

## Ctrl 与双 W 疾跑

桌面端原有 `Ctrl` 疾跑保持不变，并增加 Java 版风格的双击前进：

1. 第一次按下 W；
2. 松开；
3. 300 ms 内第二次按下 W；
4. 第二次 W 持续按住期间 `sprint=true`；
5. 松开 W 后结束这次双击疾跑。

浏览器键盘 auto-repeat 不会被误判为第二次 W。最终仍写入统一 `ControlIntentBus` 的 canonical `sprint` 状态，因此 multiplayer 不新增按键专用协议。

## 地面物品拾取优先快捷栏

`Inventory.add()` 继续保持原有主背包优先语义，避免改变合成、命令、cursor 回收等既有流程。

只有世界中的 `DropSystem` 拾取调用新的 `Inventory.addPickup()`：

1. 先合并快捷栏已有同类堆叠；
2. 再使用快捷栏空位；
3. 快捷栏无容量后才进入主背包；
4. 主背包中再执行合并和空位放置。

这样“捡起来就能直接使用”的物品优先进入 1–9 快捷栏，同时不会无意改变其他物品注入来源的排序规则。
