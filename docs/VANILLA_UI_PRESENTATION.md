# Source-backed vanilla UI presentation

## Scope

This document records the v0.4 presentation work delivered by PR #106. The goal is visual/source fidelity for the existing browser gameplay state machine; it does **not** claim full Minecraft Java 1.20.1 UI or item-model parity.

The implementation replaces hand-drawn/lookalike HUD presentation with deterministic browser assets derived from the tracked Minecraft Java 1.20.1 source archive, while keeping Inventory, Crafting, Equipment and multiplayer authority semantics unchanged.

## Source and provenance

The authoritative source remains the repository-tracked `MC原版素材assets.zip`.

PR #106 consumes these Java 1.20.1 GUI sheets:

- `textures/gui/icons.png`
- `textures/gui/widgets.png`
- `textures/gui/container/inventory.png`

`tools/build-minecraft-gui-assets.py` crops the required regions deterministically and writes browser-ready assets under `assets/gui/`. `assets/gui/gui-manifest.json` records the source/runtime provenance used by the logical asset bindings in `src/asset-manifest.js`.

The read-only `Minecraft asset source audit` workflow rebuilds these GUI outputs and compares tracked bytes against generated bytes. The workflow does not self-push generated files.

## HUD presentation contract

`src/vanilla-ui-presentation.js` installs a presentation layer over the existing UI class. It does not create a second Inventory or gameplay state machine.

The source-backed presentation covers:

- vanilla crosshair sprite;
- health hearts, including full/half/empty states;
- hunger icons, filled from the right side;
- armor icons, hidden when armor points are zero;
- experience bar background/progress and level text placement;
- 9-slot hotbar frame, per-slot background slices and selector;
- oxygen bubble sprite reuse from the source HUD sheet;
- the Java 1.20.1 survival Inventory panel background.

The desktop hotbar/status stack uses the 2x pixel presentation dimensions used by the rest of this UI pass. In particular, the hotbar is 364 CSS pixels wide including its caps.

## Survival Inventory layout

The tracked `inventory.png` panel is 176x166 source pixels and is displayed at 2x as a 352x332 CSS-pixel panel.

Existing live DOM slots are repositioned over the source panel rather than replacing Inventory logic:

- Equipment column: source `(8, 8)` -> CSS `(16, 16)`.
- Player preview region begins at source `(26, 8)` -> CSS `(52, 16)`.
- Player 2x2 crafting grid: source `(98, 18)` -> CSS `(196, 36)`.
- Crafting result: source `(154, 28)` -> CSS `(308, 56)`.
- Main 27-slot Inventory: source `(8, 84)` -> CSS `(16, 168)`.
- Hotbar row: source `(8, 142)` -> CSS `(16, 284)`.

These coordinates are presentation-only. Slot IDs, cursor semantics, crafting transactions and authoritative multiplayer paths remain the existing implementation.

The Workbench screen is intentionally not claimed as source-faithful in this PR; it keeps the existing state machine and uses the extracted vanilla-style slot texture rather than a newly imported full Workbench panel.

## Block item previews

`src/block-item-preview.js` maps supported placeable block item definitions to top/left/right terrain-atlas tiles. `src/vanilla-ui-presentation.js` renders those tiles as a deterministic three-face isometric CSS preview.

This replaces the former flat single-face block swatch in Hotbar/Inventory/Workbench presentation for supported block items. Ordinary item PNG rendering and durability overlays remain on the existing item path.

This is deliberately **not** described as full Java item-model rendering. Generic `models/item` transforms, overrides, generated-item rules and arbitrary blockstate/model resolution for inventory icons remain separate parity work.

## First-person held item synchronization

`src/immersive-game-shell.js` now recognizes `.block-item-icon` in addition to legacy `.item-icon` and `.slot-swatch` sources.

The selected hotbar item's `data-item-id` participates in the held-item signature, so changing between two different three-face block items refreshes the first-person held overlay even when their outer CSS style attributes are otherwise identical.

The bootstrap module uses static module dependencies so the main-menu event handlers are installed before browser tests or users can click through the loaded page. This removes the race introduced by a dynamic `await import('./main.js')` bootstrap.

## Deterministic runtime asset closure correction

While closing PR #106, CI exposed a historical delivery gap from the earlier generic-model asset work: documentation had described the first runtime closure as tracked, but the merged repository did not contain all generated runtime JSON files.

PR #106 closes that repository-state mismatch by tracking the deterministic outputs already required by the existing generator/audit contract:

- 9 blockstate JSON files;
- 42 block-model JSON files;
- `assets/minecraft/source-manifest.json`;
- `assets/minecraft/runtime-manifest.json`.

These files are not a new gameplay-content claim. They restore the tracked runtime closure so the read-only asset audit can rebuild the source subset and compare the full `assets/minecraft` output recursively without drift.

## Acceptance gates

A mergeable delivery must satisfy both exact-head workflows:

1. `Minecraft asset source audit`
   - rebuild deterministic GUI sprites;
   - rebuild deterministic Minecraft runtime source subset/assets;
   - byte-compare tracked GUI outputs;
   - recursively compare tracked `assets/minecraft` against generated output.
2. `Repository quality`
   - Node 22 syntax checks;
   - automatically discovered logic/server/Worker regressions;
   - both Chromium Playwright shards, including live HUD/Inventory/block-item presentation and existing multiplayer/survival regressions.

The PR remains Draft until the final documentation/code HEAD passes those exact-head gates.

## Remaining limitations

- This pass is presentation fidelity, not a complete Java 1.20.1 GUI framework.
- Full Workbench/container source panels are not implemented here.
- Generic Java item-model rendering is not implemented by the CSS three-face preview.
- Enchant glint, status-effect HUD, boss bars, recipe book and the wider set of vanilla screens remain outside this delivery.
- Existing gameplay/content limitations recorded in `docs/MINECRAFT_1_20_1_FEATURE_MATRIX.md` remain unchanged unless separately implemented and tested.
